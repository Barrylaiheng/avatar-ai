# 第 1 章 产品概述

## 1.1 产品定位

### 一句话定义

> **一款通用型 AI 客服 / AI 数字分身管理系统**（Windows 桌面应用），针对微信体系，基于 WCF 协议开发，工具本身不内置 WCF 运行时和业务内容，通过 HTTP/RPC 接口对接用户已运行的 WCF 实例，让用户通过自然语言对话或传统表单两种模式，配置属于自己的 AI 客服 / 数字分身。

### 产品形态

| 维度 | 说明 |
|------|------|
| **交付形态** | Windows 桌面安装包（.exe） |
| **运行方式** | 本地运行，数据本地存储 |
| **接入方式** | 通过 HTTP/RPC 远程对接用户已运行的 WCF（WeChatFerry）实例，工具本身不内置 WCF |
| **AI 能力** | 接入用户自备的 LLM API（DeepSeek / OpenAI 兼容协议） |
| **核心能力** | 通用消息收发 + Prompt 配置 + 知识库管理 + 消息监控 + 双模式交互（Agent 对话 / 传统工具） |
| **业务内容** | 工具不预设任何业务逻辑（如 CPS 多平台搜索、意图分类规则等），所有业务规则由用户通过配置或对话方式自定义 |

### 双模式设计要点

| 模式 | 面向场景 | 交互方式 |
|------|---------|---------|
| **Agent 对话模式** | 偏好自然语言交互、希望快速完成的用户 | 类似 TRAE / Cursor 的对话窗口，用户描述需求，Agent 调用工具完成配置、查询、操作 |
| **传统工具模式** | 偏好可视化表单、需要批量配置的用户 | 配置页、表单、下拉选项、按钮，所见即所得 |

两种模式共享同一份配置数据，可随时切换，上下文保留。

## 1.2 目标用户

### 主要用户画像

| 用户类型 | 典型场景 | 核心需求 | 付费意愿 | 优先级 |
|---------|---------|---------|---------|--------|
| **CPS 玩家 / 个人创业者** | 微信群内推广电商优惠、佣金变现 | 自定义导购话术、自动回复、商品推荐规则 | 中（省人力成本） | P0 |
| **电商客服团队** | 微信私域承接售前咨询、售后处理 | 自定义 FAQ、订单查询逻辑、转人工规则 | 中（提效） | P0 |
| **私域运营者** | 群成员管理、活动通知、社群活跃 | 自定义欢迎语、定时任务、关键词触发 | 中（提效） | P0 |
| **知识付费 / 教育机构** | 课程咨询、答疑、引流到课 | 自定义知识库、答疑 Prompt、线索收集 | 高（客单价高） | P1 |
| **品牌方 / ToB 客户** | 品牌客服、会员服务、统一话术 | 多账号管理、品牌素材库、合规审核 | 高（要求私有化） | P1 |

### 用户能力假设

| 能力维度 | 假设 |
|---------|------|
| **技术能力** | 不需要懂代码，能看懂界面操作；Agent 模式下能用自然语言描述需求 |
| **微信环境** | 用户自行在另一台电脑上配置好 WCF + 微信 + 绕过检测工具，并启动 WCF HTTP/RPC 服务 |
| **LLM 配置** | 用户能自行申请 DeepSeek / OpenAI API Key |
| **业务配置** | 用户能自行梳理业务话术、FAQ、知识库内容；工具不提供任何业务模板作为默认值 |

## 1.3 核心价值主张

### 对用户的价值

> **"不需要懂代码，你只需要描述你的客服场景或填几张表单，就能拥有一个 7×24 在线的 AI 数字分身。工具只负责通用能力，业务内容由你定义。"**

### 价值拆解

| 价值点 | 说明 |
|--------|------|
| **通用框架** | 不绑定任何业务（CPS、电商、教育都是应用场景，不是内置功能），一套工具覆盖多场景 |
| **双模交互** | Agent 对话模式让小白用户也能用自然语言完成配置；传统工具模式让老手高效批量操作 |
| **远程对接** | WCF 与业务物理隔离，用户自行管理微信环境，工具只做合规的远程调用 |
| **用户自配置** | Prompt、知识库、回复规则全部用户自定义，工具不预置任何业务模板 |
| **数据本地化** | 所有配置和对话数据本地存储，用户完全掌握数据主权 |

## 1.4 产品边界

### 做什么

| 能力域 | 说明 |
|--------|------|
| WCF 远程对接 | 通过 HTTP/RPC 调用用户已运行的 WCF 实例，收发消息、查询联系人 |
| LLM 调用封装 | 对接用户自备的 DeepSeek / OpenAI 兼容 API，封装调用链路 |
| Prompt 配置管理 | 提供系统 Prompt、业务 Prompt 的可视化管理（表单 + 对话两种模式） |
| 知识库管理 | 提供文档导入、切片、检索的通用能力（不预设任何业务知识） |
| 消息监控 | 实时展示收发消息流、处理结果、异常告警 |
| Agent 对话模式 | 通过自然语言对话完成配置、查询、操作 |
| 传统工具模式 | 通过表单、下拉、选项完成配置 |

### 不做什么

| 不做什么 | 原因 |
|---------|------|
| **不内置 WCF 运行时** | 合规隔离要求；WCF 由用户自行在另一台电脑部署 |
| **不提供 WCF 安装教程** | 不在官方文档教用户安装 WCF 和绕过检测工具 |
| **不预设 CPS 多平台搜索调度** | 业务内容由用户自配置，CPS 只是应用场景示例 |
| **不内置意图分类规则** | 意图识别由用户通过 Prompt 和知识库自定义 |
| **不内置 CPS 平台配置** | 不预置好单库 / 美团 / 淘宝等平台 API，用户按需自行接入 |
| **不做公众号 / 视频号接入** | MVP 阶段聚焦微信个人号 |
| **不做图片 / 视频生成** | 仅处理文本对话与已有素材转发 |
| **不分发 WCF 和版本绕过工具** | 合规红线 |

## 1.5 合规策略

### 三不原则

| 原则 | 具体做法 |
|------|---------|
| **不提微信 Hook** | 官方文档和宣传中使用"AI 数字分身""AI 客服助手"等概念，不强调"微信机器人""Hook" |
| **不内置 WCF** | 工具核心框架不含 WCF 运行时代码，仅通过 HTTP/RPC 远程对接用户独立部署的 WCF 实例 |
| **不提供安装教程** | 不在官方文档教用户安装 WCF 和绕过工具，由用户自行解决 |

### WCF / WS 物理拆分的安全边界

| 层级 | 部署位置 | 责任方 | 内容 |
|------|---------|--------|------|
| **WCF 层（WS 端）** | 用户自行管理的另一台电脑 | 用户 | WCF 运行时 + 微信 + 绕过检测工具 + HTTP/RPC 服务端 |
| **业务层（本工具）** | 用户本地电脑 | 用户 | AI Bridge 桌面应用，仅通过 HTTP/RPC 调用 WCF 层 |
| **合规边界** | 网络隔离 | — | 工具代码仓库不含 WCF 源码、不含绕过工具、不含安装教程；仅包含 HTTP/RPC 客户端调用代码 |

### 法规对标

| 法规 | 对标措施 |
|------|---------|
| 《互联网信息服务深度合成管理规定》 | WCF 层与业务层物理隔离，工具不分发深度合成相关工具链 |
| 《生成式人工智能服务管理暂行办法》 | LLM 调用由用户自备 API，工具不提供模型服务；用户对生成内容负责 |
| 《人工智能生成合成内容标识办法》 | 工具在生成消息中保留可配置的标识字段（由用户决定是否启用） |

## 2.2 核心功能详述

### 2.2.1 WCF 远程对接

**功能目的**：通过 HTTP/RPC 接口对接用户已运行的 WCF 实例，实现消息收发与微信账号管理。

| 项 | 说明 |
|---|---|
| **输入** | WCF 实例的 IP、端口、Token（可选） |
| **输出** | 连接状态、消息流、发送结果 |
| **处理流程** | 1) 用户在配置页填写 WCF 实例地址 → 2) 工具发起 HTTP/RPC 握手请求 → 3) WCF 返回微信账号信息（昵称、wxid） → 4) 工具建立长连接订阅消息推送 → 5) 收到消息后进入业务处理链路 |
| **异常处理** | 连接失败时给出具体原因（网络不通 / 端口未开放 / Token 错误）；断连后自动重连，3 次失败后告警 |
| **合规约束** | 工具仅包含 HTTP/RPC 客户端代码，不包含 WCF 服务端代码；连接配置不持久化 Token 明文 |

### 2.2.2 LLM 调用封装

**功能目的**：统一封装用户自备的 LLM API 调用，支持多模型切换。

| 项 | 说明 |
|---|---|
| **输入** | API Key、Base URL、模型名、温度、Prompt、上下文消息列表 |
| **输出** | LLM 响应文本、Token 用量、耗时 |
| **处理流程** | 1) 用户在配置页填写 LLM 凭证 → 2) 工具发起测试请求验证连通性 → 3) 业务流程中按场景组装 Prompt → 4) 调用 chat completion 接口（支持流式） → 5) 返回结果并记录 Token 消耗 |
| **异常处理** | API Key 无效、配额超限、网络超时分别给出明确提示 |
| **合规约束** | API Key 本地加密存储，不上传任何外部服务 |

### 2.2.3 Prompt 配置管理

**功能目的**：让用户自定义 AI 数字分身的人设、回复风格、业务规则。

| 项 | 说明 |
|---|---|
| **输入** | Prompt 名称、分类、内容、变量定义 |
| **输出** | Prompt 版本记录、调用入口 |
| **处理流程** | 1) 用户通过表单或 Agent 对话创建 Prompt → 2) 工具校验变量合法性 → 3) 保存为新版本（支持回滚） → 4) 业务流程中按场景加载对应 Prompt → 5) 变量插值后送入 LLM |
| **示例** | 用户可创建"客服问答 Prompt""售后转人工 Prompt""活动通知 Prompt"等，完全由用户定义 |
| **合规约束** | 工具不提供任何业务模板作为默认值；提供空白模板供用户填写 |

### 2.2.4 知识库管理

**功能目的**：让用户导入业务文档，供 AI 检索增强生成（RAG）。

| 项 | 说明 |
|---|---|
| **输入** | 文档文件（txt / md / pdf / docx）、切片参数 |
| **输出** | 向量索引、检索结果 |
| **处理流程** | 1) 用户上传文档 → 2) 工具按配置切片 → 3) 调用 Embedding 模型生成向量 → 4) 存入本地向量库 → 5) 业务流程中按用户消息检索 Top-K → 6) 拼接进 Prompt 送入 LLM |
| **通用性说明** | 知识库内容完全由用户决定（产品手册、FAQ、话术、课程资料等），工具不预设任何业务知识 |

### 2.2.5 消息监控

**功能目的**：实时展示 AI 数字分身的运行状态，便于调试与运营。

| 项 | 说明 |
|---|---|
| **输入** | WCF 推送的消息、LLM 调用日志、异常事件 |
| **输出** | 消息流面板、统计图表、告警通知 |
| **处理流程** | 1) 监听 WCF 消息推送 → 2) 记录每条消息的处理链路（接收 → Prompt 组装 → LLM 调用 → 发送） → 3) 异常事件触发告警 → 4) 按时间窗口聚合统计 |
| **展示维度** | 消息列表（发送方 / 接收方 / 内容 / 处理结果 / 耗时）、统计图（消息量趋势、Token 消耗、响应耗时分布） |

## 2.3 多模态交互系统

### 2.3.1 双模式设计总览

| 模式 | 交互范式 | 适合用户 | 适合场景 |
|------|---------|---------|---------|
| **Agent 对话模式** | 自然语言对话 → 意图识别 → 工具调用 → 结果反馈 | 偏好对话、小白用户、快速配置 | 一次性配置、临时查询、探索性操作 |
| **传统工具模式** | 表单 → 提交 → 反馈 | 偏好可视化、老手、批量配置 | 精细配置、批量管理、复杂参数 |

### 2.3.2 Agent 对话模式

**核心机制**：类似 TRAE / Cursor 的对话窗口，用户用自然语言描述需求，Agent 通过 LLM 进行意图识别，调用对应工具（WCF 配置、Prompt 创建、知识库导入、消息查询等）完成任务。

**意图分类（通用）**：

| 意图 | 触发示例 | 调用工具 |
|------|---------|---------|
| 配置 WCF | "帮我连接到 192.168.1.100 的 WCF" | WCF 配置工具 |
| 配置 LLM | "我用 DeepSeek，Key 是 sk-xxx" | LLM 配置工具 |
| 创建 Prompt | "帮我写一个客服 FAQ 的 Prompt" | Prompt 创建工具 |
| 导入知识库 | "把这个 PDF 导入知识库" | 知识库导入工具 |
| 查询消息 | "最近 10 条消息是什么" | 消息查询工具 |
| 查询状态 | "WCF 连上没？LLM 还能用吗？" | 状态查询工具 |
| 发送消息 | "给张三发一句你好" | 消息发送工具（需用户确认） |
| 业务咨询 | "怎么配置一个电商客服场景" | 知识库 + Prompt 建议（不内置模板，仅引导） |

**安全约束**：
- 涉及发送消息、删除数据等高风险操作，Agent 必须先展示操作预览，等用户确认后执行
- Agent 不会绕过任何合规边界（如不会教用户安装 WCF）

### 2.3.3 传统工具模式

**核心机制**：通过表单、下拉、选项、按钮完成配置，所见即所得。

**主要界面**：
- WCF 连接配置页（IP / 端口 / Token 表单）
- LLM 配置页（API Key / Base URL / 模型下拉）
- Prompt 管理页（列表 + 编辑器）
- 知识库管理页（上传 + 列表 + 切片配置）
- 消息监控页（实时流 + 统计图）

### 2.3.4 模式切换机制

| 项 | 说明 |
|---|---|
| **切换入口** | 主界面顶部全局切换按钮，两个模式图标并列 |
| **上下文保留** | 切换时保留当前正在编辑的配置、当前对话上下文、当前选中对象 |
| **状态同步** | 两个模式共享同一份配置数据，任一模式修改立即生效到另一模式 |
| **切换示例** | 用户在 Agent 对话中创建了一个 Prompt，切换到传统模式可在 Prompt 管理页看到该 Prompt 并继续编辑 |

## 2.4 MVP 范围界定

### MVP 必须包含

# 第 3 章 用户流程与交互

## 3.1 首次使用流程

### 三步引导（MVP 必须实现）

首次启动工具时，强制引导用户完成以下三步，**Prompt 配置不作为首次必填项**（用户可在后续使用中按需配置）。

```
┌────────────────┐     ┌────────────────┐     ┌────────────────┐
│  Step 1        │     │  Step 2        │     │  Step 3        │
│  WCF 连接检测   │ ──→ │  LLM 配置      │ ──→ │  测试发送      │
└────────────────┘     └────────────────┘     └────────────────┘
```

### Step 1: WCF 连接检测

| 项 | 说明 |
|---|---|
| **前置条件** | 用户已在另一台电脑上启动 WCF + 微信 + 绕过检测工具，并开启 HTTP/RPC 服务 |
| **用户操作** | 填写 WCF 实例的 IP、端口（、Token） |
| **工具动作** | 发起握手请求，获取微信账号信息（昵称、wxid） |
| **通过条件** | 收到合法的微信账号信息 |
| **失败处理** | 给出具体原因（网络不通 / 端口未开放 / Token 错误 / WCF 未启动），引导用户排查 |
| **合规提示** | 工具不提供 WCF 安装教程，仅在界面提示"请确保 WCF 已启动并开放 HTTP/RPC 端口" |

### Step 2: LLM 配置

| 项 | 说明 |
|---|---|
| **前置条件** | 用户已申请 LLM API Key（DeepSeek 或 OpenAI 兼容） |
| **用户操作** | 选择 LLM 提供商，填写 API Key、Base URL（可选）、模型名 |
| **工具动作** | 发起测试请求（如"请回复 ok"），验证连通性 |
| **通过条件** | 收到 LLM 合法响应 |
| **失败处理** | 区分 API Key 无效、配额超限、网络超时等，给出具体提示 |

### Step 3: 测试发送

| 项 | 说明 |
|---|---|
| **前置条件** | Step 1、Step 2 均通过 |
| **用户操作** | 选择一个测试联系人（或输入 wxid），输入测试消息，点击发送 |
| **工具动作** | 调用 LLM 生成回复 → 通过 WCF 发送给联系人 → 展示发送结果 |
| **通过条件** | 联系人收到消息（用户在微信端确认） |
| **失败处理** | 区分 WCF 发送失败、LLM 调用失败，给出具体提示 |
| **完成** | 三步全部通过后，进入主界面，可自由选择 Agent 对话模式或传统工具模式 |

### 首次使用流程图（双模式入口）

```
启动工具
   │
   ▼
[Step 1: WCF 连接检测] ──失败──→ 排查提示
   │通过
   ▼
[Step 2: LLM 配置]      ──失败──→ 排查提示
   │通过
   ▼
[Step 3: 测试发送]      ──失败──→ 排查提示
   │通过
   ▼
进入主界面（双模式切换入口）
   │
   ├──→ Agent 对话模式
   └──→ 传统工具模式
```

## 3.2 Agent 对话模式用户流程

### 3.2.1 对话配置流程

**场景**：用户通过自然语言完成配置。

```
用户："帮我连接到 192.168.1.100:10086 的 WCF"
   │
   ▼
Agent 意图识别 → 配置 WCF
   │
   ▼
Agent 调用 WCF 配置工具，传入 IP 和端口
   │
   ▼
工具返回连接结果（成功 / 失败原因）
   │
   ▼
Agent 反馈："已连接成功，当前微信账号是 XXX"
```

**典型对话配置场景**：

| 用户输入 | Agent 动作 |
|---------|-----------|
| "我用 DeepSeek，Key 是 sk-xxx" | 调用 LLM 配置工具，保存 Key，发起测试 |
| "帮我写一个电商客服的 Prompt" | 调用 Prompt 创建工具，生成草稿，等用户确认后保存 |
| "把这个 PDF 导入知识库" | 调用知识库导入工具，按默认参数切片 |
| "把回复温度调到 0.7" | 调用 LLM 配置工具，修改温度参数 |

### 3.2.2 对话查询流程

**场景**：用户通过自然语言查询状态或数据。

```
用户："最近 10 条消息是什么"
   │
   ▼
Agent 意图识别 → 查询消息
   │
   ▼
Agent 调用消息查询工具，参数 limit=10
   │
   ▼
工具返回消息列表
   │
   ▼
Agent 格式化反馈：
  "最近 10 条消息：
   1. 张三：你好
   2. AI：您好，请问有什么可以帮您？
   ..."
```

**典型对话查询场景**：

| 用户输入 | Agent 动作 |
|---------|-----------|
| "WCF 连上没？" | 调用状态查询工具，返回连接状态 |
| "今天发了多少条消息？" | 调用统计查询工具，返回当日发送量 |
| "LLM 还能用吗？" | 调用 LLM 测试工具，返回连通性 |
| "现在有哪些 Prompt？" | 调用 Prompt 列表工具，返回 Prompt 清单 |

### 3.2.3 对话操作流程

**场景**：用户通过自然语言执行操作（高风险操作需确认）。

```
用户："给张三发一句你好"
   │
   ▼
Agent 意图识别 → 发送消息（高风险）
   │
   ▼
Agent 展示操作预览：
  "即将执行：
   收件人：张三（wxid_xxx）
   内容：你好
   确认执行？"
   │
   ▼
用户确认 → Agent 调用消息发送工具
   │
   ▼
工具返回发送结果
   │
   ▼
Agent 反馈："已发送给张三"
```

**风险等级划分**：

| 风险等级 | 操作类型 | 是否需确认 |
|---------|---------|----------|
| 低 | 配置修改（Prompt / 知识库 / 参数） | 否，直接执行 |
| 中 | 批量操作（批量删除、批量导入） | 是，展示影响范围 |
| 高 | 消息发送、联系人操作 | 是，展示操作预览 |
| 极高 | 不可逆操作（清空数据、重置配置） | 是，二次确认 |

## 3.4 模式切换流程

### 切换机制

```

   │
   ▼

   │
   ▼
工具保存当前对话上下文
   │
   ▼
切换到传统工具模式，定位到相关配置页
   │
   ▼
用户在表单中继续编辑
   │
   ▼
点击顶部"Agent 对话模式"按钮
   │
   ▼
工具恢复之前的对话上下文
   │
   ▼
Agent 提示："已切换回对话模式，刚才你在编辑 XXX Prompt，需要继续吗？"
```

### 上下文保留机制

| 保留项 | 说明 |
|--------|------|
| **对话历史** | Agent 对话的完整消息记录 |

| **未保存草稿** | 表单中未保存的内容 |

### 切换场景示例

| 场景 | 流程 |

| 传统 → Agent | 用户在表单中填写了一半 → 切换到 Agent → 问"我这个 Prompt 还差什么" → Agent 基于当前草稿给出建议 |

### 5.1.2 分层职责

| 层级 | 部署位置 | 职责 | 包含组件 |

| **业务层** | 业务层内部 | 处理业务逻辑，不直接接触微信 | Prompt 管理、知识库、消息处理、LLM 调用 |

| **WCF 层（WS 端）** | 用户自行部署 | 运行 WCF + 微信 + 绕过工具，提供 HTTP/RPC 服务 | WCF 运行时、微信客户端、绕过检测工具 |

### 5.1.3 物理隔离的实现方式

| 隔离点 | 实现方式 |
|--------|---------|
| **代码隔离** | AI Bridge 代码仓库不包含 WCF 源码，仅包含 HTTP/RPC 客户端调用代码 |
| **部署隔离** | WCF 层部署在电脑 A，业务层部署在电脑 B，通过网络通信 |
| **分发隔离** | AI Bridge 安装包不含 WCF 二进制文件，不含绕过检测工具 |
| **文档隔离** | 官方文档不提供 WCF 安装教程，仅提供 HTTP/RPC 接口对接说明 |

# 伪代码示例
@register_tool(name="config_wcf", risk_level="low")
def config_wcf(ip: str, port: int, token: str = None):

### 1.1 场景描述

- **业务场景**：微信社群 / 私聊中的 CPS 智能导购。
- **用户行为**：群成员在群内咨询商品优惠（如"有没有奶茶优惠券""推荐个便宜的耳机"），机器人识别购物意图后，调用外部 CPS 接口搜索优惠商品，并将结果以结构化格式回复给用户。
- **运营目标**：通过自动化导购提升 CPS 转化率，同时降低人工筛选优惠信息的工作量。
- **关键说明**：本场景中的"多平台搜索调度"是用户通过 AI Bridge 的"外部 API 配置"能力实现的（如配置好单库 API、各平台 PID 等），不是框架内置功能。AI Bridge 仅提供"外部 API 配置"的通用入口与 LLM 工具调用（Function Call）能力。

## 附：场景配置通用流程

无论选择上述哪种场景，用户在 AI Bridge 中的配置流程是通用的，如下所示：

1. **对接 WCF**：用户自行解决 WCF 安装与微信接入（AI Bridge 不内置 WCF，不提供安装教程）。
2. **配置 LLM API**：在"AI 配置"中填入自备的 LLM API Key（DeepSeek / OpenAI 兼容）。
3. **配置 Prompt**：在"Prompt 配置"中粘贴自行编写的 Prompt（参考上述示例）。
4. **配置知识库**：在"知识库管理"中导入自行整理的业务文档（参考上述示例）。
5. **配置外部 API（可选）**：如场景需要调用外部接口（如 CPS 场景），在"外部 API 配置"中填入接口地址、鉴权信息、参数映射。
6. **测试与上线**：在测试环境验证交互效果，确认无误后上线。

> 以上流程为通用能力，AI Bridge 框架本身不区分场景类型，所有场景共用同一套配置入口。场景之间的差异完全由用户配置的 Prompt、知识库、外部 API 决定。
