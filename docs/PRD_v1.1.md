# 第 1 章 产品概述

## 1.1 产品定位

### 一句话定义

> **一款 CPS 业务中后台管理系统**（Windows 桌面应用），为微信 CPS 玩家提供完整的业务运营管理能力，包括消息监控、意图识别、多平台搜索调度、规则配置、数据统计等核心功能。

### 产品形态

| 维度 | 说明 |
|------|------|
| **交付形态** | Windows 桌面安装包（.exe） |
| **运行方式** | 本地运行，数据本地存储 |
| **接入方式** | 通过 WCF（WeChatFerry）接入微信个人号消息 |
| **AI 能力** | 接入用户自备的 LLM API（DeepSeek / OpenAI 兼容） |
| **核心能力** | CPS 平台配置 + 搜索策略管理 + 意图规则配置 + 运行监控 |

### 产品边界（做什么 / 不做什么）

| 做什么 | 不做什么 |
|--------|---------|
| CPS 多平台搜索调度（好单库/美团/饿了么/淘宝/京东/拼多多/淘票票/酒店） | 不开发、不分发 WCF 和版本绕过工具 |
| 意图分类规则配置（本地快通道 + LLM FC） | 不提供 WCF 安装教程 |
| 运营规则管理（三层规则体系） | 不做公众号消息接入（MVP 阶段） |
| 消息流实时监控与统计 | 不做视频号消息接入 |
| 安全壳配置（合规底线 + 业务红线） | 不做图片生成功能 |
| 品牌配置与素材管理 | 不做通用知识文档 RAG（CPS 场景用搜索调度） |

### 合规策略

采用"三不原则"：

| 原则 | 具体做法 |
|------|---------|
| **不提微信 Hook** | 官方文档和宣传中使用"数字分身""AI 助手"等概念，不强调"微信机器人""Hook" |
| **不内置 WCF** | 核心框架不带 WCF 相关代码，WCF 适配器作为独立可选模块 |
| **不提供安装教程** | 不在官方文档教用户安装 WCF 和绕过工具，由用户自行解决 |

## 1.2 目标用户

### 主要用户画像

| 用户类型 | 需求特征 | 付费意愿 | 优先级 |
|---------|---------|---------|--------|
| **CPS 玩家 / 个人创业者** | 管理多个微信群，需要智能导购、自动回复、多平台优惠搜索 | 中（省人力成本） | P0 |
| **社群运营者** | 管理多个微信群，需要智能问答和新成员引导，CPS 变现 | 中（提效） | P0 |
| **ToB 客户** | 需要为自有业务搭建专属 AI 客服，有定制化需求 | 高（但要求私有化） | P1 |

### 用户能力假设

| 能力维度 | 假设 |
|---------|------|
| **技术能力** | 不需要懂代码，但能看懂界面操作 |
| **微信环境** | 用户自行解决微信接入（WCF + 版本绕过） |
| **LLM 配置** | 用户能自行申请 DeepSeek / OpenAI API Key |
| **CPS 配置** | 用户能自行申请各 CPS 平台 API / PID |

## 1.3 核心价值主张

### 对用户的价值

> **"不需要懂代码，你只需要配置好你的 CPS 平台和运营规则，就能拥有一个 7×24 在线的智能导购助手，帮你自动识别用户需求、搜索全网优惠、促成转化。"**

### 价值拆解

| 价值点 | 说明 |
|--------|------|
| **智能导购** | 通过意图识别和多平台搜索，自动为用户推荐优惠商品 |
| **运营提效** | 7×24 自动回复，减少人工干预，提升群活跃度 |
| **规则可配** | 运营规则、搜索策略、安全壳全部可视化配置，无需改代码 |
| **数据驱动** | 实时监控消息流和处理结果，数据驱动运营优化 |
| **通用可复制** | 支持多个 CPS 平台，一套系统管理多渠道业务 |
